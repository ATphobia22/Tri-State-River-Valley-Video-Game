# River Valley Family Adventure v1.4 — graphics implementation and evidence

## What actually runs
- **Quadtree-based adaptive terrain**: the camera selects independent 16x16-grid tiles using sampled geometric error, projected pixel error, and a strict mesh budget. Nearby tiles can be level 6 while far tiles remain level 2. This is NOT the old global 64/128/256 switch.
- **Crack repair**: fine-tile boundary vertices sample the neighboring coarser tile's interpolated edge; a terrain skirt covers any residual LOD transition. Unit tests enforce terrain junction parity.
- **One terrain height path**: roads, building corners, player, foliage and stop beacons use the same currently active tiled surface. Roads are rebuilt after LOD transitions; detailed building walls are grounded to their footprint vertices.
- **Original 3D model pack**: five original low-poly glTF 2.0 GLBs (barn, riverboat, fishing pier, courthouse and cottage). Source meshes generated by `build_models.py`; the manifest lists hashes, dimensions, and model names. All five are embedded in offline HTML and displayed when 3D WebGL is available. They are stylized artistic inventions, not accurate surveys or historically authenticated architecture.
- **Environment VFX**: gradient sky shader with sun and night stars, 17 drifting cloud clusters, 1,048 ground-following flower plants, river glints. In full visual mode atmosphere is denser; lite mode reduces fog and quadtree budget.
- **Activity scenes**: fishing, hunting and cooking minigames use offline procedural canvas illustrations (works even with WebGL unavailable). These activities feed a common inventory, save slots, XP and coins.

## Tested
- `node --test tests/test-core.cjs tests/test-geometry.cjs tests/test-quadtree.cjs tests/test-models.cjs tests/test-sw.cjs` tests gameplay, tile partition, patch boundaries, aligned road surfaces, GLB structure and simulated service-worker offline routing.
- `python tests/mock3d_smoke.py`: executes the *actual Three.js scene-graph construction and LOD transitions* with a dummy WebGLRenderer. It verifies five original GLB models, dynamic mesh budgets, roads, buildings, atmosphere, and no JS exceptions. This does not prove GPU rendering.
- `python tests/ui_v12_smoke.py`, `python tests/activities_smoke.py`: Chromium 2D fallback desktop and emulated mobile interactions.
- `python tests/offline_pwa_smoke.py`: intended live service-worker test; **blocked by this testing environment** on local HTTP navigation. A Node harness tests the worker's behavior as a substitute; real offline PWA proof on a device is pending.

## Unverified or limited
- WebGL hardware output and performance; original Three.js `WebGLRenderer` fails to create a GPU context in this isolated test environment. Rendering-side GLSL shader and material compatibility should be validated in a proper GPU browser.
- Verified geospatial CRS and elevation datum; original source files include an incompletely filled DEM and derived footprint models. The game remains a fictional approximation, not survey-grade mapping.
- True CDLOD geomorphing: the implementation uses separate adaptive tiles, conforming edges and skirts; it does **not** implement vertex-shader geomorph transitions.
- Actual offline mode in iPhone Safari/Windows; standalone file:// and localhost navigation are blocked in the tool environment. Install over HTTPS and run an airplane-mode test.
- Native Windows `.exe`/Unity player and iPhone IPA. Only the browser game and independent Unity data-import starter exist.
